# ポーカー勝率予測・GTOトレーニングアプリ

テキサスホールデム用の勝率予測ツール(MVP)。React Native (Expo) + TypeScript製、サーバー通信なしのローカル完結アプリです。

## 現在のスコープ(MVP: 勝率予測ツール)

- テーブル人数 2〜10人に対応し、標準的なポジション名(UTG, MP, HJ, CO, BTN, SB, BBなど)を自動割り当て
- 自分のハンド・コミュニティカード(フロップ/ターン/リバー)をワンタップで選択
- 各相手プレイヤーの行動(フォールド/リンプ/コール/レイズ/3ベット、ポストフロップはチェック/ベット含む)を記録
- 行動履歴から簡易ヒューリスティックで各プレイヤーの推定レンジ(上位X%)を算出
- フォールド済みプレイヤーはシミュレーション対象から除外
- モンテカルロシミュレーションで自分の勝率(%)をリアルタイム算出(対戦人数に応じて試行回数を調整)
- 勝率は数値+バーで表示、ワンタップで新しいハンドにリセット

## GTOソルバー(4-2、β版)

抽象化(限定的なベットサイズ・手札バケット)を用いたチャンスサンプリングCFR(Counterfactual Regret Minimization)による近似ソルバーです。

- プリフロップ〜リバーの全ストリートに対応(解析開始ストリートを選択可能)
- 2〜6人のマルチウェイに対応(※3人以上は理論上のナッシュ均衡が保証されない旨をアプリ内に明記)
- 出力:各ノードでの推奨アクション+頻度(%)、169ハンドの13x13レンジ表(色分け)
- スタック・ポット・各プレイヤーのレンジ(上位X%)・ベットサイズ・反復回数を設定してソルブ
- ツリーをタップで辿って任意のノードの戦略を閲覧可能

**既知の制約・設計上のトレードオフ**

- 本格的なGTOソルバー(GTOWizard等)はサーバー上での大規模計算を前提としており、スマホ上でのリアルタイム全ストリート計算は非現実的です。本実装はベットサイズを1〜2種類・レイズ回数を1〜2回に制限し、手札を少数のエクイティバケットに丸める簡易抽象化により、端末上での実行を可能にしています。
- 手札バケットはポテンシャル非考慮(将来のストリートでの逆転可能性を見ない)の単純なエクイティベースです。
- 解析開始ストリートより先のストリートは、CFRの世界サンプリング上ランダムなボード展開の集計になるため、169ハンドのレンジ表ではなく「強さバケット別」の戦略チャートで表示します。
- 3人以上のプレイヤーではCFRの収束保証(ナッシュ均衡)が理論的に成立しないため、あくまで参考値・トレーニング用の目安として扱ってください。

## GTO CPU対戦(4-3、β版)

4-2のソルバーエンジンをそのまま使い、ヘッズアップ(1対1)でCPUと対戦できるゲームモードです。

- CPUは行動のたびに現在の実際の状況(ポット・スタック・ボード・ここまでの行動)からその場でサブゲームを組み立てて再ソルブし(いわゆる継続的な再ソルブ/subgame solving)、算出された混合戦略に従って確率的に行動します。事前計算した固定の戦略表を参照しているわけではありません。
- CPUの手札は実際に配られた1つの具体的なハンドに固定し、あなた(人間側)の推定レンジは4-1で実装したヒューリスティック(行動履歴からのレンジ推定)をそのまま再利用します。まだ誰も行動していない最初の局面ではレンジ推定に情報がないため、フルレンジを前提とします。
- CPUの強さは「弱い/普通/強い」の3段階(バケット数・反復回数・ベットサイズ抽象化の粗さで調整)。
- スタックはマッチをまたいで持ち越され、ボタンは1ハンドごとに交代、どちらかのスタックが尽きるとマッチ終了です。

**既知の制約**

- ヘッズアップ専用です(3人以上のCPU対戦は未対応)。
- CPUの行動選択肢は4-2と同じベットサイズ抽象化(1〜2種類のサイズ+オールイン)に限定されます。人間側は任意の金額でベット/レイズできます。
- サイドポット処理は実装していません(ヘッズアップでは不要なため問題ありませんが、3人以上に拡張する場合は別途必要です)。

## ディレクトリ構成

```
src/
  poker/
    types.ts        カード・アクション・プレイヤー等の型定義
    cards.ts         デッキ生成・カード表記ユーティリティ
    evaluator.ts      5〜7枚からの役判定(ハイカード〜ロイヤルフラッシュ)
    handRanking.ts    169通りのスターティングハンドの強さ順位付け(Chen式ベース)
    positions.ts      テーブル人数ごとのポジション構成・デフォルトオープンレンジ
    ranges.ts         行動履歴からレンジ(パーセンタイル帯)を推定するヒューリスティック
    equity.ts         モンテカルロ法による勝率シミュレーション
  solver/
    cfr.ts            汎用チャンスサンプリングCFRエンジン(ゲーム非依存)
    handStrength.ts   手札バケット化(プリフロップは正確な169ハンド順位、ポストフロップは簡易モンテカルロ)
    tree.ts            テキサスホールデム用の抽象化済みベッティングツリー構築(途中のストリートから再開する継続的な再ソルブにも対応)
    solve.ts           ソルブ実行・結果取得(ノード別/バケット別/レンジ表)のAPI
    types.ts           ソルバー用の設定・型定義
  cpu/
    gameEngine.ts      ヘッズアップの実対戦ロジック(配札・アクション・ラウンド終了判定・ショーダウン)
    cpuDecision.ts     CPUの意思決定(現在の状況から再ソルブし、混合戦略からアクションをサンプリング)
  state/
    useHandSession.ts ハンド全体の状態管理(プレイヤー・カード・ストリート・勝率計算)
  components/         カード選択・プレイヤー行・勝率表示・レンジ表などのUI部品
  screens/
    HandScreen.tsx    勝率予測ツール画面
    SolverScreen.tsx  GTOソルバー画面
    CpuMatchScreen.tsx GTO CPU対戦画面
scripts/
  validate-cfr.ts               CFRエンジンの正当性検証(クーンポーカーの厳密解と比較)
  validate-solver.ts            ベッティングツリーの不変条件検証(ペイオフ保存則・ラウンド終了判定・途中再開等)
  validate-game-engine.ts       ヘッズアップ対戦ロジックのチップ保存則・終了判定の検証
  validate-cpu-decision.ts      CPU意思決定の合法性・チップ保存則の検証
  validate-cpu-match-integration.ts  ゲームエンジン+CPU意思決定の結合動作検証(複数ハンドの通し実行)
```

## 開発

```bash
npm install
npm run ios     # または npm run android / npm run web
```

検証スクリプト(アプリには含まれません):

```bash
npx tsx scripts/validate-cfr.ts
npx tsx scripts/validate-solver.ts
npx tsx scripts/validate-game-engine.ts
npx tsx scripts/validate-cpu-decision.ts
npx tsx scripts/validate-cpu-match-integration.ts
```

## 注意事項

- レンジ推定は簡易ヒューリスティックであり、静的レンジチャートやGTO計算に基づく精緻なものではありません(今後の改善対象)。
- GTOソルバー・GTO CPU対戦は簡易抽象化による近似計算です。上記「既知の制約」を参照してください。
- 実戦補助ツールとしての利用を想定していますが、App Store配信時の審査要件は別途検討が必要です(要件定義書 5章参照)。
